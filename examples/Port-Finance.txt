> Exactly—Port’s FlashLoan instruction insists on CPI’ing a receiver program you control. To use Port in our hotpath flow we need to supply that “FlashLoan receiver” contract and pass
  its program id (plus any extra accounts) to the FlashLoan instruction. Once the receiver exists, the flow becomes:

  1. Borrow via Port’s FlashLoan.
  2. CPI into our receiver program; it executes the swap/arbitrage logic and writes the amount + fee back into the reserve.
  3. Return from CPI; the Port program verifies repayment and closes out.

  If you’d like, I can sketch the minimal receiver program (Anchor or native Solana) that:

  - Accepts the standard accounts (source/destination/token program/etc.).
  - Calls into our execution path, then transfers principal + fee back to the reserve.
  - Exposes the handler we can point Port’s FlashLoan at.

  Let me know and I’ll draft that crate along with matching unit tests so we can wire Port in once the program is deployed to devnet.
